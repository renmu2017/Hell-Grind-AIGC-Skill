# 方法论证据与使用边界

## 这份方法从哪里来

本 Skill 的方法来自对一个公开 AIGC 长片项目结构化资料的只读归纳，并结合通用电影生产、资产管理和质量控制原则重新设计。仓库只保留统计、通用规则、原创模板和原创短例，不携带原始视频、原始资产、全量提示词或长篇项目提示词。

研究对象很大，但“大”本身不是方法。真正有用的是：哪些信息反复出现、哪些生产关系可追踪、失败如何促成版本变化、生成次数和创作方案数之间有什么差异。

## 结构模式命中

对 7,482 条去重提示词做高置信度关键词和结构规则匹配，得到以下方向性结果：

| 模式 | 约占去重提示词 | 设计动作 |
|---|---:|---|
| 空间调度 | 75.9% | 明确前中后景、屏幕方向、人物站位与唯一物体 |
| 镜头或焦段 | 76.8% | 摄影机写起点、路径、稳定方式、对焦和终点 |
| 动作物理 | 75.5% | 写准备、发力、接触、反作用和落定 |
| 表演微动作 | 74.9% | 把情绪翻译为视线、呼吸、停顿和姿态 |
| 声音底层 | 68.0% | 在镜头设计阶段记录对白、拟音和环境底床 |
| 连续性 | 41.8% | 用独立矩阵管理身份、状态、轴线、动作和声音接点 |
| 负向约束 | 89.4% | 只针对当前风险，不把大量否定词误当质量 |
| 引用范围 | 21.0% | 每个参考明确继承和排除属性 |

这些比例来自规则匹配，不是完整语义标注：同义表达会漏计，宽泛词会产生少量误计。它们说明“什么值得纳入工作流”，不能证明某个词、某种长度或某种写法与生成成功存在因果关系。

## 九条证据支持的生产结论

### 1. 生成记录不是提示词库

同一提示词可重复生成很多次。必须分开记录：

- `prompt_id + version`：创作方案。
- `batch_id`：同一方案和参数的一组抽样。
- `generation_id`：一次真实结果。
- `selection_id`：一次评审决定。

若这四者混为一体，就无法判断改善来自提示词、参数还是随机差异。

### 2. 资产身份与镜头状态必须分开

“同一个角色”与“这个镜头中的角色状态”不是一回事。身份包含脸、体型、核心轮廓等稳定事实；状态包含服装版本、伤势、湿度、污渍、手持物和情绪起点。修改状态不应创建新身份，改变身份必须重新批准资产。

### 3. 参考图必须声明范围

参考图可能同时带入身份、姿态、构图、机位、光线和色彩。生产需要显式声明：

```text
继承：身份、发型、服装版本
排除：原图姿态、构图、摄影机、光线、背景、调色
```

“参考这张图”不是可控指令。

### 4. 空间关系比形容词更稳定

多人、多道具或复杂场景中，精确人数、屏幕左右、解剖左右、前中后景、出入口和接触关系应先于风格词。空间错误不能靠增加“电影感”修复。

### 5. 动作要写因果链

动作不是动词列表。可执行描述至少包含触发、准备、发力、接触、反作用和停止状态。环境也要响应重量、风、雨、碎片、液体和光照变化。

### 6. 摄影机要有结束状态

只写“推进、环绕、跟拍”没有定义镜头如何结束，也无法建立下一镜接点。摄影机契约应写起始构图、一个主运动、稳定方式、对焦对象和结束构图。

### 7. 声音是镜头契约的一部分

对白时长会挤压动作；环境声决定空间；静默决定节奏；未明确音乐边界可能产生自动配乐。声音不能等生成完成后才考虑。

### 8. 负向约束应来自失败风险

高频出现不等于应该全量复制。负向约束只保留本镜最可能的少数错误，例如额外人物、身份漂移、错误口型或自动字幕。可正向表达的内容先写正向契约。

### 9. 迭代必须隔离变量

平均 15.41 次生成说明选择非常重要，但不证明“多抽就好”。每次新版本写清改变变量、假设和预期改善；连续两个批次对同一错误无改善时，回到资产或镜头拆解，而不是继续复制同一提示词。

## 如何理解“技术底座”

研究中可观察到反复出现的摄影、光线、配色、皮肤、表演、物理、构图、连续性、帧率和声音条目。v2 将它们转化为检查维度，而不是固定附加在每个镜头后的咒语。

使用原则：

- 只选与当前镜头相关的维度。
- “自然光”必须服从场景真实光源，不能和明确棚拍主光并存。
- “60:30:10”只在需要明确颜色层级时使用。
- “180° 快门”是运动模糊语汇，不保证平台真实物理快门。
- “8K/IMAX”最多作为质感目标，实际交付规格单独记录。
- 有意手持与故障抖动分开描述。
- 导演或摄影师名字不是可检查的镜头契约，也可能带来权利或平台风险。

## 不应从数据直接推断什么

- 提示词越长越好。
- 重复次数越多，镜头越重要或越成功。
- 高频句子适用于所有模型、题材和画幅。
- 一条技术底座能自动解决身份、动作或连续性。
- 所有参考资产都是真正的正侧背三视图。
- 公开可访问等于允许重新分发。

## 使用本方法时的证据等级

| 等级 | 定义 | 写作方式 |
|---|---|---|
| 项目事实 | 已批准资产、brief、场次和镜头数据 | 直接作为硬约束 |
| 用户明确选择 | 当前请求中给出的数量、动作、台词和时长 | 直接作为硬约束 |
| 方法规则 | 本 Skill 的通用生产和提示词结构 | 作为默认流程，可被用户覆盖 |
| 方向性经验 | 研究统计和失败模式 | 标为建议，不包装成保证 |
| 假设 | 为补齐非关键细节作出的保守选择 | 单独列出，允许用户改 |

最终画面仍需人工查看；本地审计器只检查结构和显式冲突，不预测模型效果。
